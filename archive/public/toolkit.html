World Archival Toolkit

How to package a multiplayer game so the archive can keep it running.

Server package

Upload a .zip or .tar.gz that contains a Dockerfile. Use multi-arch base images. An optional vwa.json fills in the title, port, database and client.

PORT
The port your server listens on.
DATABASE_URL
Postgres connection string, when the world uses a database. The database runs in its own container with a persistent volume.
WORLD_ID
The server's identifier in the archive.

Players reach your server at /play/<id> on the archive, which proxies WebSockets to your container. Answer GET /status with a players array to show who is online.

Web client package

Upload a .zip of a browser build with an index.html: a Unity WebGL build, a web export, or an emulator page. It is served at /clients/<id>/ and should connect to /play/<server-id> on the same origin. Add a thumb.jpg for the library tile.

Example projects

The Internet Archive VR world ships a Node.js + Postgres server, a three.js WebGL client, and a Unity 6 client that share one protocol. See worlds/vrarchive/ in the repository.
